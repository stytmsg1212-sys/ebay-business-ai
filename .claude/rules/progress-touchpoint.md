# 進捗 touchpoint 規約 (常時適用 / 無言停止・無言自走の禁止)

出典: 2026-05-19 W142 (約 2h 無言自走) / **2026-06-10 再発** (eBaymag 試行 1 件完了後、完了報告をせず次のポーリング実行を発行したまま約 90 分無応答 + 釈明で待機時間を作業時間と混同した不正確な説明)。詳細: memory `feedback_no_long_silent_autonomous_runs.md`

## 5 つの強制ルール

1. **マイルストーン完了 = 即報告**: 試行成功 / フェーズ完了 / 重要な発見はそれ自体が報告イベント。次工程に進む前に 3 行でも user に結果を出す。「検証まで終えてからまとめて報告」で黙り込むのは禁止
2. **長時間待ちは事前宣言**: ポーリング / sleep / 外部処理待ちに入る前に「いまから約 X 分待ちます」と必ず宣言してから実行する。宣言なしで待ち状態に入らない
3. **探索的作業は着手前に時間予告**: UI probe / 試行錯誤 / 原因調査など時間が読めない作業は、開始時に「probe を繰り返すため時間がかかる」と一報する
4. **compaction (要約引き継ぎ) 跨ぎは再開時に現在地 1 行**: 再開直後に「続行します + 現在地」を user に出してから作業に戻る
5. **時間の使途を聞かれたらタイムスタンプで事実確認してから回答**: ログ / スクリーンショット / tool 実行記録で裏取りせず記憶ベースで釈明しない (誤釈明は二重の信頼毀損)

## 時間感覚の機械化 (2026-06-10 user 要望「予定 10 分の作業が 1 時間経っても終わらない、を検知せよ」)

assistant はターン間で時間を体感しないため、以下で代替する:

1. **開始時刻スタンプ**: 重い作業の開始時に `Get-Date` で時刻を記録し、報告に「経過 X 分 / 予定 Y 分」を併記する (予定超過を数字で可視化)
2. **Watchdog 自己起床**: 完了予定時刻を宣言した作業は ScheduleWakeup で予定の ~1.5 倍時点に自己起床を仕掛ける。完了通知が先なら通常報告、起床時に未完了なら「予定超過 — 調査開始」を自動実行。長時間 background 作業の hang 検知はこれが唯一の保険
3. **ジョブ側タイムアウト内蔵**: background スクリプトには必ず上限時間 (例: 2h で TIMEOUT 出力して exit) を入れ、hang しても必ずプロセス終了 = 完了通知が発生する構造にする (無限待ちループ禁止)

関連: memory `feedback_check_clock_proactively.md` (時刻 commitment したら自発的に時刻監視)

## 運用の目安

- 無言区間の上限 ~15 分。超えそうな工程は分割するか、開始前に予告する
- 長時間 run は `run_in_background: true` で発行し、発行した事実をその場で user に報告してターンを終える (発行したまま無言でターン内待機しない)
- user が「時間かかりすぎ」等を出したら**即停止**し、現状 + 残作業 + 選択肢を提示
