□ 価格帯別の分析
  - 高額商品の売上が落ちているか？

□ 仮説立案と対策検討
  - 競合の増加？

#### 2. eBay手数料体系と利益率 (重要度：⭐⭐⭐⭐)

**実際の費用構造**:
- Final Value Fee (最終評価料): **6%**
- Payoneer 手数料等を含めると: **実質9%程度**
- **円安の影響で、相対的なコスト負担が上昇**

**ビジネスインパクト**:
```
例）$100で販売
- eBay手数料(6%) = $6
- Payoneer等(3%) = $3
- 実質91%の利益ベース

円相場の影響:
- 1USD = 100円 → コスト9円
- 1USD = 150円 → コスト13.5円
  (円安で、日本からの仕入れコストが相対的に上昇)
```

**現在の対策**:
- 「ちょっと工夫をして価格を上げる」という言及 ⚠️
  - **注意**: この部分は音声認識が不鮮明。不正行為的な実装は避けること
  - VeRO規約（知的財産権保護）への準拠を徹底

**推奨アクション**:
```
□ 手数料を前提とした価格設定モデルを構築
□ 為替変動を月次で記録・分析
□ eBayキャンペーン活用で販売数量を増やす（手数料%は固定だが、絶対額の利益を最大化）
```

#### 3. キャンペーンクーポン活用（重要度：⭐⭐⭐⭐⭐）

**仕組み**:
- eBayは定期的にセラー向けキャンペーンを実施
- キャンペーン対象商品にはクーポン配布

**過去の成功実績**:
- 11月のキャンペーン実施時に「クーポン使って結構売れた」という実績あり
- クーポンタイミング = 買い手のモチベーション上昇タイミング

**現在の課題**:
- キャンペーン対象を見落としている可能性がある
- セラーポータルとeBay Japanページの両方を確認する必要あり

**推奨アクション（重要）**:
```
□ セラーポータル を 毎週チェック（最優先）
   - "Campaign" セクションを確認
   - 対象商品リストを確認

□ Googleカレンダーに "セラーポータル確認" を毎週リマインダー設定

□ キャンペーン対象商品の洗い出し
   - Finance部署と協力して、キャンペーン期間の売上改善効果を測定
   - 利益率向上の有無を記録

□ 11月の成功パターンを詳細分析
   - どの商品が売れたか？
   - 元々の価格設定は？
   - 割引率は？
   - これを 3月, 4月, 5月に適用

具体的フロー:
キャンペーン情報入手 → 対象商品確認 → 価格設定調整 → 在庫確認 → 売上追跡
```

#### 4. 出張・ネットワーク活動（重要度：⭐⭐⭐）

#### 2. リサーチツール統合の課題と対策（重要度：⭐⭐⭐⭐⭐）

**現状の課題**:

```
AirResearch:
  - 個人のPC内でローカル管理
  - コピー機能で Google Sheets に抽出可能
  - 複数メンバー間での共有が課題

e-stocks:
  - Google Account で登録
  - PC内ローカル管理
  - Google Account 共有のセキュリティ懸念
    (メインの Google Account を共有したくない)

全体的な課題:
  - 新規登録データが PC内に保存されてしまう
  - 複数メンバーで最新版を同期しにくい
  - 手動での共有が大変
```

**推奨ワークフロー（業界ベストプラクティス）**:

```
パターン A: Google Sheets + ChatGPT 自動整理
──────────────────────────────────
1. AirResearch でリサーチ完了
2. コピー機能でデータを抽出
3. Google Sheets にペースト
4. 初期段階: 見にくい状態（多くの不要列がある）
5. ChatGPT プロンプトエンジニアリング
   - 入力: 「AirResearch の生データ」
   - 指示: 「必要な列だけ整理。利益率、ROI、在庫数を計算」
   - 出力: きれいに整理されたデータ
6. Dropbox で全メンバーに共有 ✅

パターン B: Dropbox + Google Sheets 同期
──────────────────────────────────
- Dropbox フォルダを複数メンバーで共有
- 最新ファイルが常に Dropbox に保存されている状態
- Google Sheets を Dropbox ファイルとして保存
- 誰がアクセスしても最新版が見られる
- ただし、複数人が同時編集する場合は競合に注意
```

**Security考慮**:
```
e-stocks の Google Account 共有問題の解決:
□ ビジネス用 Google Account を別途作成
  - メイン Account: 個人用（フォト、メール等）
  - 2つ目 Account: ビジネス用（e-stocks, Google Drive 等）
  - これにより個人データの流出リスクを最小化

□ または、API連携で自動化（Engineering部署検討）
```

**実装優先度**:
```
優先度 1（今すぐ): Google Sheets + ChatGPT パターンの導入
優先度 2（1週間以内): Dropbox 共有フォルダの権限管理を設定
優先度 3（2週間以内): e-stocks用の Google Account 分離
```

#### 3. 配送方法の選択戦略（重要度：⭐⭐⭐⭐）

**現状の言及**:
- 複数シッピング方法の同時提供が可能
- 商品特性に応じた配送方法の使い分けが重要
- 日本UBIN、Speed Post, Economy等、複数の選択肢がある

**推奨される配送選択マトリックス**:

```
商品の「サイズ × 重量」 → 配送方法の決定

             軽量         重量
┌─────────────────────────────────┐
│ 小 │ Economy/  │  Express     │
│   │ Speed Post│ (時間優先)   │
├─────────────────────────────────┤
│   │           │              │
│ 大 │ Economy   │  FDX/Express │
│   │ (低コスト)│ (標準)       │
└─────────────────────────────────┘

具体例:
- 衣類（小・軽）→ Economy（最安値）
- カメラレンズ（小・重）→ Express（破損リスク軽減）
- 電化製品（大・重）→ FDX（実績あり）
- 書籍（大・軽）→ Economy または Speed Post
```

**実装アクション**:
```
□ 現在の商品ポートフォリオで「サイズ × 重量」を分類
□ 各配送方法のコスト・リードタイム・保険料を調査
□ 配送選択マトリックスを Google Sheets で実装
□ 出品時に自動選択できるロジックを構築（Engineering部署）
```
