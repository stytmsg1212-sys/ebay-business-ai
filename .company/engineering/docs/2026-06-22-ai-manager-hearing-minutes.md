## 1. ★ 値付けの背骨（最重要・オーナー確認済）

**入口の問い =「有効な競合の中で、"利益が出る範囲での最安" を取れるか？」**

1. **取れる** → **有効最安を $0.1 差で取る**（有在庫なら 1日発送で勝つ）。**例外**: ソールド数で圧倒し、最安でなくても Best Match で一番上を取れる時は、最安より上で**据え置き**。
2. **取れない（最安にすると赤字・薄利すぎ）** → **総合判断**（キーセラー軸、§4）。
3. **"利益が出る最安" が存在しない** → **撤退/放置**（§6）。

→ **値上げ・値下げ・撤退は同じ 1 本のルール**。市場（ライバル価格）が動けば、この「利益が出る最安」という目標が上下するだけ。値上げは別ロジックではなく、市場回復でルールが上に動いたもの。

⚠️ **重要な訂正点（CodexとFuguが両者指摘、オーナー合意）**: ここで言う「最安」は**生の検索結果の最安ではなく、門前払いフィルタ（§3）を通過した"有効競合"の中の実質最安**。生の最安には JUNK / 評価稼ぎ / DDU 等の偽ライバルが混ざり、追随すると損をする。

## 2. 「十分な利益」の線（背骨の分岐点）

実コード `calculator.py:_check_listable` に実装済の**価格帯別ハイブリッド**（金額 AND 率、両方必須）:

| 販売価格 | 最低利益額 | 最低利益率 |
|---|---|---|
| ≤ $30 | 500円 | 25% |
| ≤ $100 | 1,000円 | 20% |
| ≤ $300 | 2,000円 | 15% |
| $300超 | 5,000円 | 12% |

- コンサル「けいすけ基準」(初期1年目): 利益率 **6%** / 利益額 **600円**（撒き餌商品は別）。
- 仕入先採用 `check_supplier_candidate_profitable`: 600円床 + スライド率10-20%。**※600円床は「還付抜き利益」で判定すべき（オーナー判断でバグ修正済・未コミット）。スライド率の分母を還付抜きにするかは未決の論点**。

## 3. 判断①「そもそもライバルか」（門前払いフィルタ）

- **日本人セラーのみがライバル**。海外セラーは相手にしない（国=JP で判定、GetItem で取得可）。
- **判断は「検索結果の一覧」で行う**。個別の商品ページは**開かない・説明文は読まない**（例外は DDU 疑いの検証時のみ、後述）。
- **商品同一性**:
  - 自分が動作品なら、相手 **JUNK / AS-IS は完全無視**（別土俵）。
  - 状態判定 = **タイトルの NEW / USED / AS-IS / JUNK** × **写真の状態**の掛け合わせ。eBay の**コンディション欄は見ていない**。
  - **見抜きにくい仕様差**（例: 背面の電圧切替スイッチの有無、ケーブル長）。**オーナー本人でも見逃し、発送後にバイヤークレームで発覚した実例あり**。AIにも難所。
- **評価稼ぎの弱小セラー**（低評価 × 赤字価格）= **無視**。狙いは利益でなく評価集めで、利益度外視の価格を付ける。**ただし実際に数を売って自分の売上を奪っているなら無視解除**（安全弁）。
  - 補足: これが「最安はたいてい弱小セラー」の正体。だから背骨の"最安"は弱小を除いた有効最安。
  - 評価数が低くても**普通の価格**なら無視せず競合視（=最安にして利益が出るなら自分が最安を取る）。
- **DDU セラー判定（3段階）**:
  1. **疑うトリガー** = ①価格が明らかに安い × ②送料に関税分が乗っていない × ③**評価数1000以上**（評価が低ければただの弱小=無視で済む。評価が高いのに安い="何か狙いがある"と疑う）。
  2. **検証** = その時だけ商品ページを開き、**説明文に「関税を含まない」系の文言**があるか確認 → あれば DDU 確定。
  3. **ブラックリスト** = DDU セラーIDを**育つリストに追記**（user/AI が気づくたび追加）。リスト入りは追随しない。
  - 補足: ②③①は GetItem で全取得可、検証の説明文も GetItem の Description で読めるので**AIで自動再現可能**。

## 4. 判断②「どこまで価格で対抗するか」（対抗強度）

- **キーセラー概念（核心）**: 本当の相手は「**最安ではないが、ソールド数も評価数も多い"ちゃんと売っているセラー"**」。最安は弱小=無視。**値付けはこのキーセラーとの勝負を一番深く考えている**。
- **強豪認定**: 評価数 **≥1000 かつ 評価率 ≥98%**。**1000超は一律**（1000も5万も同じ扱い）。背景 = 買い手の心の**天秤**「早く届く嬉しさ ⇔ 数千評価による安心感」。相手の評価が高いと安心感が勝ち、自社の1日発送だけでは引き留めきれない → 価格で対抗。
- **ソールド数優位 → 強気（値下げしない）**: 相手よりソールド数が**明確に多い**時。
  - 1桁台は対象外（相手1→自分3=3倍でもダメ、絶対数が低すぎる）。相手5→自分15なら強気もありうる。桁が上がってからの3倍は「分かりにくい」=きれいな数値ルールは無い。
  - **本質的な判断 =「ベストマッチで検索して、最安でなくても自分が一番上を取れるか」**。取れるなら据え置き。ソールド数優位はその原因。**取れない時は最安+1日発送に戻る**。比較対象は**キーセラー（特定の1人）**。
- **1日発送レバー**: **有在庫の時のみ**使える。相手（キーセラー）は7日発送が多い。基本戦略 = 最安を **$0.1差**で取り、同じ価格帯に入り込んで1日発送で勝つ。
- **状態ポジショニング**（USED同士）: 自分より**汚い商品（安）**と**綺麗な商品（高）**があれば、**その間の値段**に置く。**早く回したい時**は、汚い安商品と**同額**にして（綺麗なのに同価格=お得感）**数を多く売る**。**回転数・自分の在庫数**も影響。
- **在庫種別で分岐**:
  - **無在庫** = 仕入先が相手と同じ可能性 → 差別化できない（1日発送も無理）→ **最安一択**。
  - **有在庫** = キーセラー/ソールド数/状態/回転/在庫数の**総合判断**。
- **床 = 絶対に赤字にしない**。例外: **ポイント利益**が乗るなら、**回転の速い商品**で薄利の**長期戦**（自分がキーセラーに育つ）もあり。

## 5. 仕入れ（在庫補充）※満足だが記録

- **パターンA（Amazon/楽天=安定供給品）**: 安定価格で常に仕入れ可。**在庫が減ったら補充** + **セール時に2-3個まとめ買い**。
- **パターンB（メルカリ/ヤフオク=主に中古）**: 有在庫で売ると決めた商品を、**安い玉が出たタイミングで確保**（ライバルに取られる前に押さえる=機会型）。
- **「売れる確信」= テラピークの販売実績**: **月2-3個**売れていれば仕入れる。月1個でも安ければ仕入れるかも。
- **基準価格 = メルカリ/ヤフオクの過去の落札（売れた）平均**。**買いトリガー = 平均より約20%安い時**（商品により変動。例: 平均¥10,000 → ¥8,000以下なら買う）。
- **20%の理由（重要）= 下振れ保護**。それだけ安く買えれば、もし海外（eBay）で売れなくても、**日本のヤフオクに再出品して赤字を防げる**。
  - ⚠️ この有在庫仕入れの判断は**コンサルKBには未収録**（コンサル動画の内容がKB化されていない）。本議事録が唯一の正本。

## 6. 撤退（出品をやめる/引く）

**有在庫** → **基本"撤退しない"**（撤退=損確定）。最安でも赤字の状態でも、**利益が取れる価格で放置して売れるまで待つ**。時間を置けば価格帯が上がり、放置していた商品がいつの間にか売れる。

**無在庫** → これも赤字にならないので「撤退」より「**利益取れる価格で放置**」が多い。撤退トリガーは3つ:
1. **仕入れ元が消滅**（年1-2個しか出回らないヤフオク希少品）→ **在庫0で放置**、再び出回ったら仕入れて販売。
2. **eBayから警告**（警告が来やすい特定ブランド）→ **即撤退**。具体例: **Holbein の色鉛筆**。※`vero_brands.json` は CLAUDE.md に記載があるが**実体ファイルが存在しない**ことが判明 → 警告/VeRO要注意ブランドの**育つリストを新規に作るべき**（Holbein を第1号）。
3. **インド人がよく買う商品** → 撤退。理由 = **購入後のメッセージが非常に多く、CS対応の手間が利益に見合わない（費用対効果が悪い）**。事前予測は不可、**売ってみてインド人購入+問い合わせ多発で気づく反応型**。
   - 補足: AIなら注文データの「買い手の国」+商品別メッセージ数から**自動検知できる**（オーナーが勘で予測できない領域をAIがデータで拾える）。

## 10. リサーチ相互フィードバック学習（計画）

毎日のループ:
1. 本日売れた商品をもとに、**オーナーと AI が各自リサーチ**。
2. オーナーは「**この商品を見つけた / 選んだ理由**」を AI に伝える。
3. AI も結果を出す。
4. **オーナーが AI の結果を添削**。
5. 添削・選定理由を**メモリ（Obsidian連携で AI の頭脳に蓄積）**に記録。
6. AI は**次回リサーチ前に必ず読む**（Q7 read-first）→ 日々リサーチ力が上がる。

**永続化の実体**: `C:\Users\gucch\obsidian-vault` 内のジャンクション `memory → 私のメモリ`（+ `company → .company`）で双方向同期。オーナーが Obsidian に書いたものが AI の知識になる。

## 11. 安全設計（Codex/Fugu 合議・AI店長 実装時の必須ガード）

- **採用と自動値下げの分離**: ライバル「採用（監視対象）」と「値下げ適格（pricing_eligible）」を DB で分離。W183 自動値下げは `pricing_eligible=1` のみ参照（偽ライバル採用→自動追従→損失 を遮断）。
- **Shadowモード**: 本番の自動値下げに繋ぐ前 1〜2週間、AI判定と人間判断を突合し誤採用率を実測。
- **fail-closed / abstain**: 関税不明・データ不足・状態不確実なら「据え置き/abstain」。アクション集合に `abstain` と `SKU撤退` を追加。
- **レートリミット**: 1回/1日/1週の最大値下げ幅・回数・累積上限、kill switch。
- **money-direct = 提案止まり**: 価格・仕入れは AI が提案、実行ボタンは user（W183 既存の floor 付き自動値下げのみ例外）。
- **無在庫の値下げは履行ゲート**（仕入先在庫の鮮度確認）。**1日発送を名乗る実条件**（検品/カットオフ/休業日）確認。

## 13. 追加ヒアリングで確定（2026-06-23、Codex 漏れ指摘を埋めた補足）

### 13.1 §3補足: 商品同一性「見抜きにくい仕様差」（3トラップ・全て検知困難）
- ①電圧切替スイッチの有無 ②ケーブル長 ③**言語/地域版**（日本語版を「英語に切替可」と思われ購入 → 英語化不可でクレーム。例: スピーカーのアンプ、ボイスレコーダー。画面メニューの有無はまちまち=ジャンル特定困難）。
- **防御方針**: 出品文に「英語化不可」等は**書かない**（書くと売上が落ちる）= **リスク承知で受容**。→ AI店長は出品文を変えず、せいぜい「言語版リスクあり」の**内部フラグ（user 気づき用）**に留める。
- 付属品欠け/世代違い等の他トラップは「今のところ無い」。

### 13.2 §4補足: 中古「綺麗さ」の状態ポジショニング（確定原則）
- **チェック7項目**: 傷 / 黄ばみ / 液晶の映り / 箱・取説 / パッケージの破れ / 付属品の欠け / 全体の使用感。箱・取説・付属品ありはプラス。
- **固定額の目安は無し**。全て**ライバルとの相対**。
- **★確定原則**: 「**自分の商品の価値を（状態+付属品）で判断 → ライバル一覧の中で自分がどこに位置するか判断 → その位置に応じた適正価格をつける**」。
- **背骨の精緻化**: §1の「最安を取る」は正確には「**状態込みで位置取りし、同条件の中では最安、自分が状態で上位なら一覧の上位に位置取り**」= 単純最安でなく状態込みの相対ポジショニング。

### 13.3 §2補足: 利益床と撒き餌（確定）
- **自動値付けの床 = 価格帯別ハイブリッド表（§2）で確定**。
- **撒き餌 = 利益は取れないが回転が良く、売ることで SEO が向上する商品**。指定は **user**（AIは勝手に赤字で売らない）。
- **AI店長の役割**: 撒き餌商品も監視し、**ライバルが消えて利益が取れる状態になったら「昇格（値上げで利益化）」を提案**。

### 13.4 §4補足: ソールド数の見方（確定）
- ソールド数 = **GetItem QuantitySold（累計・期間指定なし）**。
- 判断は **「自分 vs 相手」の相対比**。きれいな倍率ルールは無い（本人も「3倍は曖昧」）。
- **★最終判断は「実際に Best Match 検索して、最安でなくても自分が一番上に来るか」**。ソールド比は目安、**Best Match の実順位が正**。一番上を取れない時は最安+1日発送に戻る。

### 13.5 §3補足: 海外セラー（確定・例外なし）
- **常に日本人セラーのみ競合視。海外セラーは無視（例外なし・困った経験なし）**。
- 海外セラーは安いことが多く日本人セラーが売れないこともあるが、**競わない**。理由 = 他国は品質が劣ることが多く、**「日本ブランド」で差別化**。価格敏感層は海外に譲り、品質重視層を取る戦略。
- → AI店長は海外セラーが安くても**動じない**（門前払いフィルタで国≠JP を除外、想定内）。

### 13.6 §6補足: 撤退の優先順位（確定）
- **インド人撤退の閾値**: インド購入は毎回、問い合わせ+関税対応+値下げ交渉で**平均10通以上**のやり取り。人件費を考えると数千円の利益は割に合わない。→ **1販売あたり10通以上**が撤退候補の目安。AIは「インド購入 × メッセージ多発」で検知。
- **警告/VeRO は最優先・即削除**: 有在庫の「基本撤退しない」原則を**上書き**。警告が来たら**損切りしてでも即リスティング削除**（アカウント毀損 ≫ 数万円の損失）。

### 13.7 §11補足: 安全設計（確定・簡素化）
- **最大値下げ幅 / 価格 ceiling 等の数値は設けない**。

> **⚠️ 2026-07-02 改訂 (user)**: 上記「最大値下げ幅の数値は設けない」を上書きし、**値下げは 1 回 5% まで** + **同一商品が連続 3 回値下げでアラート**を安全弁として追加。理由: ライバルも同種の自動値下げシステムを使う想定で、高速な値下げ合戦 (スパイラル) の検知・抑止が必要と判断。旧見解 (2026-06-23) は「床 lp_min_price のみで十分」だったが、値下げ合戦シナリオを考慮して数値上限を採用。

- **唯一の歯止め = 商品ごとに事前設定する「赤字ライン（床）」**（= `lp_min_price`）。AIはそれより下げない。
- 判断①フィルタ（farmer/DDU/junk/海外を追わない）と床で十分。
- **立ち上げ = Shadow（提案のみ・値段は変えず）期間から → 動作確認 → 良ければ自動へ昇格**（user 合意）。

## 付録: 本ヒアリングの手法（再利用のため）

- **Critical Decision Method (CDM)**（Klein/Crandall/Hoffman 1998）: 抽象ルールでなく**具体的な過去の1ケースを再生**してもらい、cue（何を見たか）と判断を掘る。
- **Thinking Aloud**: 実データ（実際の検索結果スクショ等）を見ながら判断を実況。
- **backtracking**（清水久三子）: 相手の答えを言い換えて確認し、さらに掘る。
- **funnel / 仮説力**（野口吉昭）: 仮説をぶつけて確認（例: 背骨「利益が出る最安」を仮説提示→確認）。
- **一問一答**: 一度に一つだけ深掘り、まとめ・実装に走らない。
