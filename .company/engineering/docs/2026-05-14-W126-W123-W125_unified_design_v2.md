## 2. Background

### 2.1 OneDrive 配下の実害 risk (W126 の根拠)

| risk | 我々への影響 | 経験 |
|---|---|---|
| **file lock** | scheduler が monitor.db / log 書込中に OneDrive sync 競合 | W95 (5/3) で経験済 |
| **DB corruption** | SQLite 公式が non-local 配置を非推奨、同期中の write で破損 | latent |
| **conflict copy** | `filename - PCname.md` 自動生成 | hook で検出ロジック実装済 (= 過去対応経験あり) |
| **junction sync 不全** | OneDrive が junction を sync しない or sync pending 永続化 | architect 指摘、未経験だが Obsidian 採用で顕在化 |
| **`.git/` sync 試行** | objects/ の数十万小ファイルで超低速 + conflict | git 未導入のため未顕在化 |
| **secret 露出** | OneDrive Web 経由でアクセス可能、cloud breach 時の risk | latent、`.env` に多数の API key |

### 2.2 Karpathy LLM Wiki Paradigm (再掲)

3 層 (Raw / Wiki / Schema) × 3 操作 (Ingest / Query / Lint)。我々は ~80% 既実装、不足は **cascade update / 矛盾アノテーション / lint deterministic checks** で Phase 0 absorb。

### 2.3 Obsidian 1.12 の質的変化 (W123 の根拠)

- **built-in CLI** (100+ commands、2026-02 リリース): CLI-centric user でも terminal 完結
- **kepano 公式 Agent Skills** (2026-01-02): markdown / CLI / Bases / Canvas / Web Clipper の 5 種、Claude Code 公式対応
- **多 AI 共通 substrate**: vault を GitHub 同期すれば Claude / Codex / ChatGPT 全部読める

### 2.4 Codex CLI の現状 (W124-W125 の根拠)

- 独立 CLI (`npm i -g @openai/codex`)、Claude Code と同型 UX
- ChatGPT Plus に **token credit 制で含まれる** (使い放題ではない、Week 2 で実測必須)
- MCP server モードあるが対話 loop 向き、我々の用途は Bash `codex exec --json` 直叩きで surgical

#### Decision D: 移行手順 (12 step、scheduler 停止許容時間 ~3h)

```

  1. backup: robocopy /MIR で OneDrive 内全コピーを C:\backup_2026-05-14\ に
  2. inventory: 移行対象 / 除外ファイル一覧化 (ls + size + count)
  3. path 参照箇所 grep: rg "C:.\\OneDrive.\\work.\\claude" --files-with-matches で全 hit 抽出

Phase 1-B: 実行 (2h、scheduler 停止)
  4. scheduler 停止: Stop-Process PID 38996 + 確認 (logs/scheduler.log の最終行)
  5. monitor.db 整合性確認: sqlite3 monitor.db "PRAGMA integrity_check"
  6. 新 path に copy: robocopy OneDrive 配下 → C:\Users\gucch\projects\claude\ /MIR /COPYALL /R:3
  7. 全 path 参照を新 path に書換: PowerShell 一括 replace (CLAUDE.md / scheduler config / .env 等)
  8. .gitignore 配置
  9. git init + git add . + git commit -m "Initial migration from OneDrive"
  10. GitHub private repo 作成 (user 操作 ~5min) + git remote add origin + git push -u origin main
  11. scheduler を新 path から起動: pythonw tools/ebay-manager/daily_scheduler.py
  12. 動作検証: scheduler.log の起動メッセージ、cron 登録、monitor.db 書込

Phase 1-C: 検証期間 (1 週間、OneDrive copy 保持)
  13. 日次 git push の自動化検討 (cron task or user 操作)
  14. scheduler 稼働状況 monitor
  15. 7 日間異常なしを確認後、OneDrive 内 project フォルダを archive
```
