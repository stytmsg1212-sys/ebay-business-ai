1. 業務概要 — 何のビジネスか

業務理解 最終更新 2026-05-25

日本国内のフリマ / オークション / 量販店から商品を仕入れ、eBay (北米向け中心) に出品する 越境 EC 物販ビジネス。1 人運営、利益直結なので「自動化精度 = 売上」に直結する。

収益モデル + 主要規制
  • 収益源: 仕入額 (JPY) と eBay 売上 (USD) の差額 - eBay 手数料 - 配送料 - 関税 (DDP 売主負担) - 為替損益
  • 米国向け = DDP 出荷 = 関税は 売主負担 (Negative feedback 防止だが利益直撃)。第 4 章 業務ドメイン規約 参照
  • Section 232 派生品関税 25% (鉄鋼・アルミ含む 84-87 章) で 1 商品 ~$200 売主負担、赤字化リスクあり
  • VeRO ブランド (Apple / Nintendo / SONY 等) は非正規ルート品で出品禁止 → アカウント停止リスク

4. 業務ドメイン規約 — DDP / Section 232 / SKU / コンディション 8 段階 / VeRO

業務理解 違反 = 金銭事故 最終更新 2026-05-25

⚠️ 本章は「絶対ルール」の集約。違反 = 売上喪失 / アカウント停止 / 関税赤字直結

4-1. DDP 出荷 (米国向け)

Delivered Duty Paid = 関税は売主負担。販売価格に関税 buffer 必須 (最低 15%)。

販売価格設計式:
販売価格 = 原価 + 国際送料 + 関税 buffer + PLS 2% + eBay fee + 利益

4-2. Section 232 関税 (鉄鋼・アルミ派生品)

Annex税率条件該当例
I-A50%重量閾値なしHS 73xx 鉄鋼 / 76xx アルミ / 74xx 銅
I-B25%metal weight ≥ 15%HS 8516 炊飯器 / 8418 冷蔵 / 8708 自動車部品
III15%transitional ~2027-12-31HS 8421 ろ過 / 8428 産業ロボット

4-3. SKU 用途は 2 つだけ

在庫種別SKU 形式性質
有在庫stock** (stock:01 / stock1 等)同一 SKU を複数 listing が持つのが正常
無在庫ebay**_***** (例 ebayyh_p1221413657)SKU 変換 → 仕入先 URL
絶対禁止: SKU を listing 主キーとして使う。WHERE sku=? / GROUP BY sku / UNIQUE(sku) / JOIN ON sku=sku 全部 NG。listing 識別は ebay_item_id。詳細は .claude/rules/sku-rules.md

4-5. eBay 出品文の禁止事項

  • ❌ Country of Origin / Country of Manufacture: Title / HTML description / Item Specifics に絶対記載しない (関税リスク)
  • ❌ Manufacturer 欄: eBay XML builder は空文字列で送出
  • ✅ 通関書類のみ: Manufacturer = 日本代理店、End Use = 実用途 (resale / 中国本社禁止)

4-6. VeRO ブランド

Apple / Nintendo / SONY 等の VeRO 該当ブランドは data/vero_brands.json で事前判定。非正規ルート品は出品しない (アカウント停止リスク)。

14-1. 症状別 検索

定時実行が動いてない (= Discord に通知が来ない)
  1. scheduler 生存確認: Get-Process -Id (Get-Content data/scheduler.pid)
  2. 死んでたら 13-2 で再起動
  3. 生きてたら scheduler.log tail で最後の発火時刻確認
  4. task 別の最終 success: DB SELECT MAX(finished_at) FROM task_execution_log WHERE task_key='xxx'
  5. 原因不明なら scheduler_health_check の最新 message を見る
MonoDeck が真っ白 / エラー画面
  1. data/streamlit.log tail で traceback
  2. MonoDeck PID kill → 13-1 で再起動
  3. session_state 関連なら browser tab reload (R キー)
DB locked / database is locked
  1. WAL competition: 長時間 transaction を持つ task (news_check 等) と log_api_call が衝突
  2. 原因 task の transaction 短縮が根治 (5/25 commit c746daf で対応済)
  3. 緊急回避: scheduler 再起動で transaction reset
eBay 出品の状態が DB と違う
  1. eBay 側が正 (第 11 章データ信頼度参照)
  2. ebay_sync を手動 invoke で強制同期
  3. 差分が大きい場合は ebay_listings backup + 全件 re-sync
仕入先 OOS / FedEx / DHL bot 検知で失敗
  1. Discord 通知に「手動更新の手順」が記載される (5/25 強化済)
  2. fuel_surcharge: 公式 URL で値確認 → MonoDeck「全体設定」タブで手入力
  3. OOS retry: paypay HTTP 500 は構造的 error、W161 Playwright fallback で対応予定

14-2. やってはいけない操作

  • ❌ git push --force origin/main (履歴破壊)
  • ❌ data/monitor.db 直接 SQL UPDATE/DELETE (Q2 6 step なし)
  • ❌ .env を git add
