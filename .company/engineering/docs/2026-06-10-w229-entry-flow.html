2. 毎晩 03:30 の処理フロー

1

クォータ残量チェック (門番)

  • Terapeak の読み取りは 1 日 ~250 回が実運用上の限界 (未実証・アカウントリスクあり) で、日曜 02:00 の市場分析と共有
  • 当日の消費実績を DB (api_call_log) で集計し、残りが足りなければ今日は中止 → Discord で「クォータ不足で skip」通知 (黙って消えない)
↓残量 OK
2

結果リストの収穫 (harvest_product_list) — 2 パターン × 各カテゴリ

  • 各カテゴリに対して ① fresh_24h と ② two_year_echo の 2 パターンを実行し、結果を合算
  • ① Last 7 days / Date last sold 新しい順 → 直近 24 時間以内の行だけ採取 (「いま売れた」鮮度型)
  • ② Last 2 years / Date last sold 古い順 → 「今日−2年」の 24 時間窓 (≈730日前) の行だけ採取 (年周期・再発掘型)
  • 合算で 最大 50 商品/日。①優先で詰めた後、残枠を②へ。②が 0 件の夜も正常 (Discord に痕跡)
  • 取るもの: 商品名 / Avg sold price (平均売値 $) / 90日 sold 件数 / Date last sold / 詳細リンク / 画像
  • 除外キーワード一致はこの時点で捨てる (件数はログに記録)
↓商品リスト (〜50 件)
3

重複排除 (既に判定済みの商品は飛ばす)

  • 新着順なので同じ商品が毎晩再登場する → 商品名を正規化したキーで過去判定を照合
  • 判定済み → skip (件数を記録)。例外: 「出品されたばかりで様子見」だった商品だけは再判定 (時間が経てば死に筋か売れ筋か分かるため)
↓未判定の商品のみ
4

商品ごとの詳細取得 (scrape_product_detail)

  • 90 日の sold 件数を取得 → 2 件以上ならこれだけで「対象」確定。残りの取得はスキップ (クォータ約 3 割節約)
  • 2 件未満のときだけ追加で: 現在の出品 (ACTIVE) の有無と最古の出品開始日 + 1〜2 年前の sold 件数 を取得
  • 1 商品ごとにランダム待機 (人間らしい間隔)。並行アクセスはしない
↓売れ行きデータ 3 点セット
5

売れ行きゲート 5 分岐 (自動判定・純関数)

けいすけ流の選別基準をそのままコード化した既存関数 (W228 で実装・テスト済) に流し込む:

① 対象 (在庫あり想定)直近 90 日に 2 個以上売れた → フリマ探索へ
④ 対象 (在庫 0 + 監視)今は出品ゼロだが 1〜2 年前に 2 個以上売れた → 仕入先が出たら狙う
③ 今回skip (様子見)出品はあるが開始から 90 日未満で実績不明 → 再出現時に再判定
② 死に筋 除外90 日以上出品されているのに売れていない
⑤ 需要なし 除外過去 1〜2 年でも 2 個未満
次工程へ進む 次工程へ進む (在庫0ルート) 保留 (後日再判定) 除外 (理由つきで保存)
↓判定結果
6

DB へ永続保存 (Phase 1 で整備した受け皿)

  • 全商品を research_candidates へ保存: 判定結果 / 判定根拠 / 判定に使った数字のスナップショット / 日時
  • 除外した商品も理由つきで残す (翌晩の重複排除キーになる + 後から「なぜ落としたか」追える)
  • 通過商品 (①④) は status = gate_passed → 04:30 のフリマ探索バッチが拾う
↓
7

Discord 通知 (実行サマリ)

「発掘 N 件 / ゲート通過 M 件 / 除外 K 件 / 既判定スキップ J 件」を毎朝通知。MonoDeck 定時実行タブにも表示。

3. 異常時の動き (アカウント保護が最優先)

事象動き
eBay がエラーページへ飛ばす (anti-bot の兆候)即座に全停止 + Discord 通知。残りは翌晩に持ち越し (粘らない)
取得が連続 5 回失敗同上 (既存の市場分析と同じ防御を流用)
画面の集計期間が指定とずれている (90日指定なのに30日表示等)抽出せずエラー記録 (誤った数字でゲート判定しない / 既存防御の流用)
クォータ不足 / CDP Chrome 未起動・ログイン切れ当日 skip + Discord 通知 (silent skip 禁止)

まとめ: 入り口の流れは「①2 パターン × 各カテゴリでフィルタをかけて候補を拾う → ②重複を飛ばす → ③商品ごとに売れ行き 3 点を取る → ④5 分岐ゲートで自動選別 → ⑤全件理由つきで DB 保存 → ⑥朝 Discord 報告」。 毎晩 fresh_24h (いま売れた) と two_year_echo (2年前に売れた) の 2 本立てで合算 50 件を取る設計です。 判定ロジックと受け皿と防御は完成済みで、残る作業は Terapeak 画面の読み取り部分 (実機 probe → セレクタ確定 / 期間・ソート param 確定 → バッチ化) です。
