▶ 本セッションで発生した実際の呼出フロー (LD-S9 出品バグ修正例)
1 User → 私 (Opus 4.7) 「VerifyAdd エラー: category not valid」
2 私 → rank_classifier (Haiku) 直接 Anthropic API 呼出 (ランク判定検証)
3 私 → eBay Taxonomy API (有効 leaf カテゴリ取得)
4 私 (Edit/Write) コード修正 + pytest
5 私 → code-reviewer delegate (HIGH 確認 → 2件 指摘)
6 私 HIGH 2件 修正 + regression test 追加
7 私 → code-reviewer 再確認 (HIGH=0 confirmed)
8 私 → Playwright MCP Streamlit UI E2E 検証 → User 報告

凡例 — Opus 4.7 = 複雑判断/コード生成 Sonnet 4.6 = 通常コード/出品文生成 Haiku 4.5 = 軽量分類/要約 Gemini 2.5 Flash = 動画学習

色分け — 緑=User / 水色=Main / 橙=eBay専用 / 紫=Claude組込 / 黄=cc-company / 青=MCP / 赤=アプリ内蔵API

レイヤーの意味 — ③④ は **対話ベースのサブエージェント** (Task tool 経由で呼出)。 ⑥ は **アプリ内で Python から直接 Anthropic API を叩く AI 機能** (サブエージェントではない)。 ⑤ は **ナレッジ集約用の仮想組織フォルダ** (.company/)。
